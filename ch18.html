18Goals 与 Ideas

一句话：Goals 管你已经认下的长期方向，做成一本只增不改的账本；Ideas 管它替你想的新点子，摆成一排有保质期的货架。两件合起来，回答的是个人 Agent 最难的一道题——它到底该多主动。

底层设计原理：主动性是一道光谱，不是一个开关

个人 Agent 有个天生的矛盾。太被动，它只是个问答机；太主动，它就替你做主。Muse 的解法不是选一头，而是把主动性切成三层，每层的主动程度和控制权安排都不一样：

层谁定方向Agent 能做什么控制权留在哪
目标层（Goals）用户记账、提醒、研习、写简报方向完全归用户，Agent 不许改目标本身
建议层（Ideas）Agent 提案想点子、摆上货架开工权归用户，点一下才动手
执行层（见第 06 章）Agent 拟动作真正产生副作用否决权归用户，审批不过就停

三层拼起来就是一条规矩：越接近真实世界，闸门越紧。想点子不要钱，所以 Ideas 可以放开想；记账没有副作用，所以 Goals 可以自动记；真要动手花钱发消息，就进审批。主动性每升一档，控制权就多留一手——这是整套设计的主轴。

为什么 Goals 是账本，不是待办清单

待办清单记的是未来：做完一条，划掉一条，历史归零。账本记的是过去：每一笔都留着，不许涂改。

长期目标的价值恰恰在历史，不在清单。一个练手艺的目标，练了三个月，中间断过两次、换过一次方法、某周突然开窍——这些起伏才是下次判断「还值不值得继续」「该怎么帮」的依据。清单划掉就没了，账本翻开全在。所以 Goals 的核心动作不是「打勾」，是「记一笔」：每次进展追加一条带日期的条目，目标的历史就是这样一笔笔攒出来的。文档明文

推论也很直接：账本一旦能改，信任就没了。所以进展条目只追加、不回改；记错了，正确做法是再记一笔更正，而不是回去涂掉原条目。

为什么状态只有两档：简单性本身就是设计目标

目标的状态只有两个：进行中、已完成。没有暂停，没有搁置，没有延期。文档明文

这不是偷懒，是刻意的取舍。状态每多一档，所有用到状态的地方都要跟着多一条分支：推送要不要发、简报要不要写、界面怎么显示、恢复时怎么算。两档状态下，这些问题全都一句话能答完。系统宁可让「暂停」这种真实需求绕路走，也不肯让状态机膨胀：

  • 只是不想被打扰：静音这个目标的主动推送，状态还是进行中。
  • 真的歇一阵：记一笔进展，写明在休整，账本里留痕。
  • 彻底放下再说：先标记完成，以后想捡再重新打开。

三条出路分别对应三种「暂停」，都不需要新状态。代价是用户得学一下这三条路怎么分——设计把复杂度从系统里挪到了说明书里，这是自觉的选择。

为什么 Ideas 要剥夺 Agent 的删除权

Ideas 有一条很反直觉的规矩：Agent 没有删除或忽略卡片的工具。卡片只能由用户长按关掉，或者到期自动下架。Agent 连「这张卡过时了，我帮你清掉」都做不到。文档明文

原因在于提案者的身份。Agent 既是点子的提出者，如果再兼任货架的清道夫，用户就永远分不清：这张卡不见了，是过期了、被我关了、还是它自己觉得不好悄悄撤了？货架上少了什么，必须有且只有一个解释来源。所以宁可让货架偶尔显得乱一点，也要保住可解释性：每张卡的去向，要么是用户亲手关的，要么是到期规则拿走的，没有第三种可能。

同一条逻辑也管着过期时间：约两周自动下架。文档明文有限货架逼着建议保持新鲜，也让「想法不见了」有一个默认答案——多半是老化，不是被谁动了手脚。

底层实现原理：Goals 的数据模型

拆开看，一个目标由四部分组成：

  • 目标本体：标题和描述，可改；状态两档，进行中或已完成。
  • 子目标：只许嵌一层，目标下可以有子目标，子目标下不能再有。防止目标树长成迷宫。在界面点「加子目标」不是弹表单，而是发一条聊天消息，由 Agent 在对话里建。文档明文
  • 进展账本：带日期的条目序列，只追加。目标的「详情」本质上就是这本账。
  • 简报信（briefings）：后台进程写给目标的信，渲染成 Letter，附在目标页上，另附一句短说明。它不是 Agent 随叫随写的：节奏由系统控制，不能按需生成，也不能承诺几点送到；目标可能暂时还没有简报。用户可以单独删掉某封简报。

最容易被误解的一点：目标本身不干活。目标不会自己查资料、自己推进、自己完成任务。真正让目标「动起来」的，只有绑在它身上的定时任务（cron）——到点触发一个完整的 Agent 任务去干活，干完把进展记回账本。目标是账，cron 是手，两者分工写得很死。文档明文

底层实现原理：Ideas 的生命周期

一张卡片的一生分五段：

  • 策展生成：候选点子由后台的想法策展循环产出（第 16 章提过，它按可行性、与用户的契合度、新颖度打分排序）。细节在那章，这里只接结果。
  • 上架：入选的点子变成卡片，进 Ideas 页签。部分点子还会以帖子的形式出现在 Feed 里——内容流和行动流共用同一个入口。
  • 一键构建：卡片自带构建动作，网页上写着「Let's do it」。点了，Agent 就照着卡片把东西做出来。建议和交付之间不隔第二次沟通。
  • 构建回路：构建不是发出去就完事——它就是一次正常的 Agent 任务，过程和结果回到对话里，用户能看、能改、能追加。平台还有差异：卡片发进聊天后，Android 上可以原地运行并显示实时进度，iPhone 上点开是详情页、不原地运行；Feed 里的点子帖则在所有平台都带同一个构建按钮。文档明文
  • 下架：只有两条路——用户长按关掉，或约两周到期自动退休。Agent 全程没有手。

底层实现原理：目标研习后台

目标还有一个专属的后台循环：每日夜间为每个进行中的目标查资料、整理新进展、更新简报素材，并给出推进提醒。它甚至会主动建议用户「暗示过但没明说」的目标——比如你连着几周在聊一件事却从没立项，它会把这件事提名成一个候选新目标，等你点头。合理推断

这一节只交代它与 Goals 的接口：研习的产出有三个落点——写进简报信、变成一条提醒、在目标页附上新材料。循环本身的调度、打分与克制规则属于后台系统，见第 11 章和第 16 章，这里不重复。

具体实现方式：目标工作区的真实结构

落到文件层面，每个目标在 Agent 的工作区里有一个自己的目录。用户给它看的文件、它产出的简报、它的内部状态，物理分开放：

workspace/goals/<目标 slug>/
├─ GOAL.md          # 目标本体：标题、描述、状态、创建与更新时间
├─ files/           # 给用户看的交付物，进目标页、进 Library
├─ briefs/          # 后台研习产出的简报信，按日期落盘
└─ hidden_files/    # 内部状态：检查记录、水位线、已读清单，用户不可见

这套分工和全站的文件哲学一致（第 10 章）：交付物和内部账目必须分家。用户在目标页看到的是 files 和 briefs；hidden_files 里是后台循环的草稿纸——比如上次研习查到哪了、哪些材料已经处理过。恢复时先读这里，就不会把办过的事重办一遍。实测

具体实现方式：走查一次「目标被推进」

设一个普通目标：把一门新手艺练到能独立完成作品。全程走一遍：

  • 第 1 步，用户记一笔。用户在聊天里说「这周练完了第三个模块，卡在收尾手法上」。Agent 把它落成一条带日期的进展条目，追加进账本。注意：记的是事实和卡点，不是感想流水账。
  • 第 2 步，账本更新。目标的详情页多了一条历史。状态仍是进行中，什么都没被划掉——账本只长个，不瘦身。
  • 第 3 步，后台研习。当晚的研习循环读到新条目，围绕「收尾手法」去查资料、找教程，把有用的整理成素材，记下处理水位，避免下次重复查同一批。
  • 第 4 步，简报信到达。到了系统的节奏点，一封简报信附到目标页：一句短说明加上正文——这周的进展小结、卡点的解法链接、下一步建议。用户点开目标就能看到。
  • 第 5 步，用户决策。用户看完简报，决定照建议继续练。这一步如果想让目标自己往前跑，他还可以给目标绑一个定时任务，比如每周日晚自动汇总本周练习记录——从这一刻起，「推进」才有了机械的手。

整条链里，Agent 做了四件事：记账、研习、写信、提醒。没有一件事是它替用户「练」了手艺。目标层的本分就是如此：它负责让方向不被遗忘，不负责替你走路。

具体实现方式：走查一张 Ideas 卡片的一生

  • 出现。后台策展从近期对话里嗅到一个机会——比如你总在手工拼某种报表——生成候选，打分过线，变成卡片上了 Ideas 页，文案写清「我能替你做一个自动拼报表的工具」。
  • 被点中。你点「Let's do it」。构建当场启动，按卡片描述把工具做出来，交付回到对话里，你试用、提修改，它接着改——卡片到此完成使命。
  • 或者被关掉。你觉得没用，长按把它关掉。这是你的手，账记得很清楚。
  • 或者过期。你一直没理它。约两周后它自动下架。哪天你想起来问「那个报表的点子呢」，答案是：老化退休了，不是被谁删了。要是还想要，重新让它想一个就行。
📌 删除目标的规矩单独说清：删目标是连带清除——子目标和全部历史一并删掉，界面会先要一次确认。正因如此，官方口径是：目标做完或放弃，都应该标记完成，而不是删除。删除只留给「建错了」这一种情况。标记完成的目标账本还在，随时能翻、能重开；删掉的就什么都不剩了。文档明文

边界与代价

  • 两档状态的代价：没有暂停，长期休眠的目标会一直以「进行中」的面目存在，列表可能越攒越长。缓解靠静音和标记完成，但都要用户动手。
  • 简报节奏不可控：简报信什么时候来，由系统说了算，用户不能催、Agent 不能承诺。急脾气的人会觉得它「不听话」——这是把调度权收归系统的必然后果。
  • 账本靠记账纪律：进展记得勤不勤，直接决定目标页有没有价值。用户三周不汇报，账本就是三周的空白，研习也巧妇难为无米之炊。
  • 两周期限可能误伤：点子过期是按时间一刀切，不看内容价值。偶尔的好点子会被时间拿走，只能重新生成。
  • 主动建议的边界：研习会提名用户没明说的目标。提名是建议层的事，点头才算数；它要是越过这条线直接建目标，就破坏了三层光谱的第一层。
