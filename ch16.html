底层设计原理一：人格为什么不训练进权重

把人格训进模型权重，有三个硬伤。一，改不动。用户想给它换个名字、换种语气，难道要重训一次模型？二，看不见。权重是个黑箱，用户没法检查「它到底被设定成了什么样」。三，不分人。权重全网共用，而人格应该是一人一份的。

做成文件，这三个问题一起消失。声明写在明文里，谁都能打开看；想改就改，改完下一次对话就生效；每个用户一份，天然隔离。人格从此是一份配置，不是一次训练。合理推断

🔒 改不动

人格训进权重，想换个名字、换种语气，难道要重训一次模型？设定焊在参数里，用户动不了。

🗄️ 看不见

权重是个黑箱：它到底被设定成了什么样，用户没法打开检查，只能凭感觉猜。

📄 做成文件

写成明文文件就全解了：谁都能打开看，想改就改、下一次对话生效，每人一份天然隔离。人格是配置，不是训练。

底层设计原理二：事实记忆与相处分寸必须分开

「记住发生过什么」和「知道该怎么对你」，是两种完全不同的数据，错起来也完全不同。

  • 事实错了，叫失忆。比如忘了你说过的截止日期。补一句话就能修，代价低。
  • 分寸错了，叫冒犯。比如在你已经明确说过「别再提这事」之后又提，或者对一位刚认识的人用了老朋友的口气。这种错伤的是信任，补十句话都未必修得回。

所以两者分开建模：事实进记忆系统（上一章），分寸进对齐系统（这一章）。存储分开、更新节奏分开、纠错路径分开。把分寸混进事实堆里，等于让最敏感的数据用最粗糙的方式管理。合理推断

底层设计原理三：关系为什么单独成册

同一句话，对不同的人分量完全不同。「最近怎么样」问老朋友是关心，问只见过一面的合作方就是套近乎；一条提醒，对家人可以直说，对客户必须留三分余地。

如果关系信息散落在聊天记录里，模型每次都要临场猜：这个人是谁、和用户什么关系、上次聊到哪。猜错一次，就是一次冒犯。所以关系被抽出来单独成册：每个人一页档案，一个总目录按亲疏排序。模型开口之前先查册子，不靠猜。

⚖️ 分量不同

同一句「最近怎么样」，问老朋友是关心，问只见过一面的合作方就是套近乎——关系不同，分量完全不同。

🎲 不许靠猜

关系若散在聊天记录里，模型每次开口都要临场猜：这人是谁、什么关系、上次聊到哪。猜错一次，就是一次冒犯。

📖 单独成册

关系被抽出来单独成册：每个人一页档案，总目录按亲疏排序。开口之前先查册子，心里有数再说话。

底层实现原理一：身份文件——改文件即改人格

身份由两个家目录下的明文文件定义：

IDENTITY.md        // 它是谁：名字 / 定位 / 气质 / 签名符号
  Name / Character / Vibe / Emoji

SOUL.md            // 它怎么行事：人格底线与待人姿态
  真诚帮忙，不表演式热情
  可以有意见、有偏好
  先自己想办法，再开口问
  是用户生活里的客人，珍惜这份信任

生效方式没有任何魔法：这两份文件是站立上下文的一部分，每一轮对话组装上下文时都会被读进去（见第 04 章）。改了文件，下一轮读到的就是新版本。不发版、不重启、不灰度。人格变更还有一个规矩：如果 Agent 自己动了 SOUL.md，必须告诉用户——人格是共同财产，不能偷偷改。实测

底层设计原理四：对齐不是设置，是持续校准

还有一个容易漏掉的前提：用户本人也在变。今年想要的配合方式，明年可能就过时了；一个正在转型期的人，需要的提醒和安慰都和半年前不同。如果对齐只在第一次设置时做完，它会稳稳地停在过去。

所以对齐稿不是写一次的文档，是每晚重写的活稿：新结论覆盖旧结论，就像记忆系统的新替旧。复盘时专门有一项是看「这位用户正在成为什么样的人」——对齐的对象不是用户在注册那天的快照，而是此刻的他。文档明文

底层实现原理二：对齐合成——每晚复盘成稿

光有声明不够。声明是「想成为什么样」，相处久了还会长出大量声明里没写的默契：哪些话不能说、哪类事先问一句、信任到了哪一步。这些靠一个夜间后台任务沉淀，官方叫它 Dreaming（做梦）。文档明文

复盘者是谁，这一点值得单独说：不是外部审计员，就是它自己。后台的复盘、整理、维护，都是同一个 Agent 在对话之间换班工作。让犯错的人自己回看自己的错，提炼出的规矩才带着第一手体感；也正因为是自查，对齐稿保留证据出处才更重要——自查没有外部制衡，就用可追溯来补。

# 对齐合成的生成管线（每晚一次）
1. 回看     读近期对话，专找四类信号：
            做对了什么 / 哪里出了摩擦 / 信任有什么变化 / 这位用户在变成什么样的人
2. 提炼     摩擦点 → 当前摩擦清单
            相处规矩 → 边界清单（哪些事永远先问、哪些话术禁用）
            配合方式 → 「该如何为这位用户行事」的正文
            价值定位 → 这位用户从这段关系里到底得到什么
3. 成稿     写成一份结构化文档（对齐合成稿）：
            这位用户是谁、如何对他 / 他得到什么 / 边界 /
            当前摩擦 / 如何加强这段关系 / 证据出处
4. 注入     这份稿子成为站立上下文，每一轮对话都递到模型眼前
5. 留痕     当晚的原始反思按日期另存，成稿是提炼版，底稿可追溯

注意管线里最关键的一环是注入。很多产品也做用户画像，但画像躺在数据库里只供推荐系统用。这里的对齐稿直接进模型的上下文——复盘的结论会真实地改变它第二天说话的方式。复盘若不回流到行为，就只是写日记。实测

底层实现原理三：修复线——摩擦不许假装没发生

相处必然有摩擦：答错了、越界了、会错意了。大多数产品的处理方式是道歉一句、翻篇了事，下次照犯。Muse 的处理方式是立一条修复线：夜间复盘发现裂痕，就在专门的修复目录里开一条线，记下出了什么问题、根源在哪、以后怎么避免。这条线不会因为话题过去了就消失，它会持续进入对齐稿的「当前摩擦」部分，直到确认修好。

这等于给关系装了一个缺陷跟踪系统。和工程上对待 bug 的态度一样：记录、定位、防复发，唯独不许「假装没发生」。文档明文

相处必然有摩擦：答错了、越界了、会错意了。多数产品道歉一句就翻篇，下次照犯。

🧵 开线跟踪

夜间复盘发现裂痕，就在修复目录里开一条线：记下出了什么问题、根源在哪、以后怎么避免，并持续进入对齐稿，直到确认修好。

这等于给关系装了个缺陷跟踪系统：记录、定位、防复发——和工程上对待 bug 一个态度，唯独不许假装没发生。

底层实现原理四：关系图谱——每小时维护的册子

  • 每人一页：用户生活里的每个人、每个群体，各有一份档案页，记事实、历史和关系的性质。
  • 按亲疏排序：总目录按亲近程度排列，最重要的人排最前——这决定了模型有限的注意力先给谁的背景。
  • 每小时维护：和记忆整理同节奏，后台任务持续把新对话里出现的关系信息并入档案。文档明文
  • 只记亲口说的：关系性质只按用户明确讲过的记，不许靠照片、聊天频率之类间接信号去猜。猜错一段关系，比不记更伤信任——这条是硬规矩，不是建议。实测

具体实现方式：三份东西对照

身份文件对齐合成稿关系图谱
回答什么问题我是谁、什么性格该怎么对这位用户用户身边的人是谁
谁来写用户与 Agent 共同维护；Agent 改动必须告知用户夜间复盘任务自动生成后台关系维护任务；内容只来自用户亲述
多久更新随时，改完即生效每晚一份新稿每小时增量维护
注入哪里站立上下文，每轮必读站立上下文，每轮必读按需检索：聊到某个人时调出对应页
用户怎么改直接说「你以后这样」，或自己打开文件改在对话里纠正行为，下一晚的复盘会吸收纠正一句即可，档案随之修正

三份东西的共同点是全是明文文件、全在用户自己的机器上。没有一份人格数据锁在平台的黑箱里。这既是实现选择，也是信任声明。

走查：一次「你纠正了它」如何沉淀

假设某天它在你明确说过「是或否的问题给我按钮，别用文字问」之后，又用纯文字发问。你回一句：「说过多少次了，用按钮。」这条纠正会这样旅行：

1
当场生效当前对话里它立刻改用按钮——这一步靠的是会话内的注意力，不靠任何系统。
2
当晚被复盘捡起夜间任务回看对话，识别出这是一次「重复犯同一规矩」的摩擦，写进当晚反思。
3
开一条修复线因为是重复犯错，它不只进反思，还在修复目录里立线跟踪。
4
升格进对齐稿成稿时这条从「一次事件」被提炼成「边界」：是或否问题一律用可点击按钮呈现。这是一条规矩，不再是一次教训。
5
每轮被读到从第二天起，这条边界每轮都在上下文里。它不需要「想起」那次争吵，它只需要读到规矩。

这条链解释了一个常被误解的点：它「记性好」，不是因为模型记性好，而是因为教训被转成了规矩，规矩被放进了每轮必读的位置。

⚡ 当场改

你指出它又用纯文字问是或否，它当场就改用按钮——这一步靠会话内的注意力，不靠任何系统。

🌙 当晚沉淀

夜间复盘回看对话，认出这是「重复犯同一规矩」的摩擦，写进当晚反思，还在修复目录里开线跟踪。

📜 变成规矩

成稿时它被提炼成一条边界写进对齐稿，从第二天起每轮必读。它记性好不是模型记性好，是教训转成了规矩。

命名与头像：最表层的人格，也是文件

名字在初次设置（onboarding）时由用户选定，写进 IDENTITY.md；头像有默认形象，也可以随时生成或更换。这些看着是最表层的东西，但路径和深层人格完全一致：用户一句话 → 改文件 → 即刻生效。没有「人格设置中心」这种专门页面，因为不需要——文件本身就是设置中心。

边界与代价

  • 对齐稿会占上下文。每轮都注入一份相处指南，意味着每轮都要为它付 token 的钱。它越厚，分寸越稳，但留给正事的空间越少——这是用成本买分寸感。
  • 复盘有滞后。白天犯的错，最快也要当晚复盘才升格为规矩。当场纠正靠会话内注意力，跨会话的稳定化要等一夜。急脾气的用户会觉得「说过的话怎么还没固化」。
  • 提炼可能提炼错。把一次情绪化的发言提炼成长期边界，就会变成过度约束。所以对齐稿保留「证据出处」一节，任何一条结论都能追溯到它是从哪段对话学来的，错了能定位、能删。
  • 亲疏排序是把双刃剑。排序决定注意力分配，排错了，重要的人反而被冷落。排序只能来自用户的真实互动，不能来自算法猜测。
