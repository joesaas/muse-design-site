15Memory 设计

一句话：模型本身没有记忆，Muse 就把记忆做成一套外置文件——分三层存放、按纪律写入、随时可查可删，让无状态的模型表现得像「一直记得你」。

底层设计原理：记忆为什么必须外置、分层、严进

先回到第一性。一次大模型推理的输入在开始那刻就固定，它读不到上一次对话。所以「记得你」这件事，模型自己做不到，必须由运行时在模型之外造出来：把事实存下来，下次推理前再递到它眼前。记忆系统的全部设计，都是围绕这一条展开的。

为什么分层，不用一个大库？因为三类东西的用法完全不同。最要紧的少数事实，每轮都要用，贵在「必达」；海量的历史细节，偶尔才查，贵在「能找」；这次对话的完整往返，只服务于「刚才说到哪」，贵在「连续」。全塞进一个库，要么每轮把海量数据都递给模型，上下文被撑爆；要么全靠检索，最要紧的事实反而可能漏检。分层就是按访问方式分工：

📌 站立记忆提炼后的长期事实与偏好，每轮直接注入，不检索、不等待
🗄 可检索档案按日期的笔记 + 人物/群体档案，平时躺着，相关时才搜出来
🎞 会话轨迹事件日志：这次对话的完整往返，是连续性的依据

为什么「记什么」的纪律比「记多少」更重要？因为记忆是有污染成本的。一条错记落了盘，会在之后每一轮被当成事实递给模型，错误会被反复放大；而纠正它，又要找到源头、处理所有引用过它的地方。相比之下，漏记一条，代价只是下次再问一遍。所以写入端宁严勿滥：只记耐久的事实、偏好、决定、承诺和关系，不记流水账，不记一时情绪。

轨迹层算不算记忆？严格说，会话轨迹记的是「这次聊了什么」，不是关于用户的长期事实。但它归记忆系统一并管，因为两者共同决定了模型下一轮「知道多少」：长期事实给它立场，轨迹给它上下文。把两件事在概念上分清、在工程上合管，是这层存在的理由。

为什么用文件，不用向量黑箱？向量库查得快，但用户打不开、看不懂、改不动。文件是明文：用户随时能看「它到底记了我什么」，错了能改，烦了能全删。记忆系统最大的风险不是记不住，是记错了还没人能查。用可审计换信任，这是刻意的取舍。实测

底层实现原理：存取、写入、召回、遗忘四条管线

存取：三层三种读法。站立层是文件，每轮组装上下文时整段注入，读的是「最新版全文」；档案层靠语义检索，按问题搜出相关片段再注入，读的是「命中的几条」；轨迹层靠事件重放，按序折叠出对话记录，读的是「完整经过」。三种读法对应三种成本：注入最稳但占篇幅，检索最省但可能漏，重放最全但最慢。

写入：一条四段管线。对话中出现值得记的东西，先由主 Agent 提炼成一条独立的事实主张（claim），而不是把原话整段抄下；落盘前查重，并与旧记录对账——有冲突先和解：新结论覆盖旧结论，但不直接抹掉旧的；然后写入当天笔记。最后还有一道后台整理（记忆维护循环的一部分）：把每日笔记里够格的内容提升进站立层，把过时内容降级出去。文档明文

  • 新替旧，旧账不烧：被覆盖的结论会在每日笔记里留下「已被取代」的痕迹和演变过程。人的情况会变，记忆要能纠错；纠错要能追溯，就不能物理删除历史。实测
  • 记忆的颗粒度是一条 claim：每条记忆只装一个可以独立判断真假的主张，不装一段话。颗粒细，更正时才能只动一条、遗忘时才能只删一条、溯源时才能只查一条；一段话里混着三件事实，其中一件变了，整段都无从下手。
  • 写入有多个入口，都要过提炼关：聊天里直接说「记住这个」可以，后台自动记也可以，从别的 AI 导入也可以——但都必须经过提炼与确认，没有一条是「原材料直接入库」。

召回：先搜，再答。纪律是硬性的：哪怕问题看起来和历史无关，回答前也先搜一遍记忆。原因是用户最不能忍的不是答错，而是「跟你说过的事你又忘了」。召回时还要分清来源的时间语义：一条记录说的是「当时他这么说」，不等于「现在仍然如此」——涉及现状的事实，要再核对，不能拿旧记录当现状。

还有一个细节：检索命中的片段不是裸文本进上下文，而是带着出处——来自哪个文件、第几行，都标在片段旁边。模型因此能分清「这是记忆里存的」和「这是用户这轮刚说的」，引用记忆回答时也能把来源亮给用户看，而不是含糊地说「我记得」。实测

两套搜索，必须分开。「你是谁」查记忆系统，「你说过什么」查聊天记录，是两个独立的系统。文档明文混在一起有两个坏处：一是检索会被海量对话原文淹没，提炼过的事实反而排不到前面；二是边界不清——记忆是被确认过的长期事实，聊天原文只是说过的话，两者的可信等级不同，不能混用。

导入的提炼关：上传 ≠ 存入。从 ChatGPT、Claude 等产品迁入时有两条路：把一段官方提示词粘到对方那里、拿回一份关于你的 Markdown 摘要再导入；或者上传聊天记录导出包（ZIP，上限 100 MB）让系统总结。两条路的终点相同：主 Agent 提炼出长期事实，并明确告诉用户它到底存了什么，由用户确认。只上传文件、没走完提炼和确认，等于什么都没存；导入也不会把对方的应用设置搬过来，更不会把旧对话恢复成聊天。文档明文

遗忘：三段式，不是删一行字。「忘掉某事」走专门的技能流程：第一段盘点——这条记忆存在哪些副本、哪些派生材料引用过它、哪些后台任务将来还会把它重新生成出来，列成范围给用户确认；第二段按确认的计划执行清除，包括堵住「未来产生者」；第三段验证并说明结果——删干净了什么、有没有删不到的地方，如实交代。只删源头不堵产生者，过几天它又会被后台整理重新写回来，等于没忘。文档明文

具体实现方式：文件体系与一条记忆的生老病死

落到磁盘上，记忆就是一个普通目录，谁都能打开看：

~ 家目录
├─ MEMORY.md                  站立层：提炼后的长期记忆总册
│    └─ 内部按 Facts / Preferences / Commitments 分区
├─ memory/
│  ├─ 2026-10-15.md           每日笔记：按日期、按主题小节记录
│  ├─ 2026-10-14.md           ……一天一册，只追加、留演变痕迹
│  ├─ people/
│  │   ├─ INDEX.md            人物总索引，按亲疏排序
│  │   └─ <某人>.md         一人一页：事实、历史、关系性质
│  ├─ groups/
│  │   ├─ INDEX.md            群体总索引
│  │   └─ <某群>.md         一群一页
│  ├─ bank/                    运行时维护的沉淀区（经验、观点、反思等）
│  └─ index/                   运行时管理的检索索引，Agent 只读
└─ side-chats/<chat-id>/
   ├─ MEMORY.md               侧聊天有自己的记忆空间
   └─ memory/                  与主聊天分开存放，互不串扰

注意两个细节。一是运行时在管的东西（bank、index）对 Agent 是只读的——能写记忆的是提炼管线，不能随手改索引。二是侧聊天的记忆独立成套：每个侧聊天有自己的 MEMORY.md 和 memory 目录。这与 Feed 的纪律呼应：有些材料明确不跨界流动。

一条记忆的生命周期走查（五幕，全部真实存在）：

  • 诞生：用户在对话里随口说了一句长期偏好。主 Agent 判断它耐久、可复用，提炼成一条 claim，查过没有冲突，写进当天笔记。
  • 晋升：后台整理时发现这条被反复印证，分量够了，把它提升进 MEMORY.md 的 Preferences 区——从此每轮注入，不再依赖检索命中。
  • 召回：几天后用户问一个看似无关的问题。Agent 先搜记忆，命中这条，用它校准了回答，而不是重新问用户一遍。
  • 更正：用户改了主意。新 claim 落盘并取代旧 claim；旧的降级回每日笔记并标注被谁取代。之后被问起「你怎么知道的」，能一路查回源头。
  • 遗忘：用户说忘掉它。盘点发现它存在于站立层、每日笔记和一份人物页里，逐项列明，用户确认范围后清除并验证，向用户交代结果。

来源可追溯：每条记忆都有户口。系统提供专门的溯源查询（memory_explain）：给一条记忆，能查到它的类型与重要程度、最初是谁在何时说的（带原话引用）、第一次学到与最近一次被印证的时间、当前置信度、它依据的对话消息（带日期），以及完整的替代谱系——它取代过谁、又被谁取代。记忆因此不是「模型好像记得」，而是一笔笔有出处、有账可查的记录。查不到依据时，规矩是明说查不到，不许从结果倒编一个理由出来。实测

边界与代价：哪些没公开、哪些是拿成本换的

  • 检索算法未公开：档案层用语义检索是可观察的行为，但具体用哪种 embedding、如何排序、阈值多少，文档没有写明，属未知，不猜作定论。合理推断
  • 底层存储格式未公开：用户可见层是 Markdown 文件；bank 与 index 的内部格式由运行时管理，文档未展开。
  • 分层的代价是延迟与不一致窗口：刚记下的事实先进每日笔记，晋升到站立层要等后台整理；这中间它只能靠检索被找到，存在「记了但没每轮带着」的时间窗。
  • 严进的代价是漏记：提炼关会误杀——当时没判断出价值的话，日后想找只能去翻聊天记录那套系统。系统选择接受这个代价，因为污染比漏记难收拾得多。
  • 站立层有容量上限：每轮注入的东西都要占上下文，记忆越攒越多，注入成本线性上涨。所以站立层必须保持精简，靠晋升和降级维持新陈代谢；「全都记住、全部带着」在这套架构里物理上不成立。
  • 可审计的代价是人要参与：冲突和解、导入确认、遗忘范围确认，都需要用户或主 Agent 逐项过目。这套系统本质上是「人机合写的账本」，不是全自动的黑箱记忆。
📌 证据分级小结：本章的三层结构、写入纪律、遗忘三段流程来自对真实目录与文件的实地查看（实测）；两套搜索分离、导入流程与「上传≠存入」来自官方 memory 文档（文档明文）；每小时整理与晋升/降级节奏来自运行行为的观察（实测），其内部调度实现未公开；语义检索的算法与索引格式未公开，标注为推断与未知。核心结论只有一句：记忆不是模型的功能，是运行时用文件、纪律和审计给无状态模型搭的一套外置器官。
